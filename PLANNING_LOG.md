- 2026-10-21 — dim_aircraft is derived from staging.aircraft, not identical to it: it has a surrogate key, an "unknown" member row that aircraft absent from the catalogue point to, an `in_catalog` flag (false for the unknown member, true for every catalogue row) so that "not in the catalogue" can be told apart from "in the catalogue but operator unknown", and a NULL operator replaced by 'Unknown'. Reason for the unknown member: 17.7% of observed aircraft (about 12.4% of positions) are absent from the catalogue (measured 2026-10-14); without a member to point at, their transits would either fail the foreign key or be dropped, understating traffic. Reason for replacing NULL: NULL falls out of GROUP BY and joins, silently hiding rows — decided by: user (confirming agent's proposal)
- 2026-10-21 — dim_aircraft uses a surrogate key, not the natural key (icao24). Reasons: the unknown member has no icao24 and a primary key cannot be NULL; a made-up placeholder such as 000000 would collide with a real catalogue row (000000 is one); and a surrogate key is what makes SCD2 possible later, since SCD2 needs two rows for one aircraft. Consequence accepted: because staging.aircraft is rebuilt from scratch on every run, dim_aircraft must NOT be rebuilt that way — an icao24 gets its surrogate key when first seen and keeps it for good (new aircraft get new keys, existing aircraft may have their attributes updated), otherwise fact-table keys would silently point at different aircraft — decided by: user (confirming agent's proposal)
- 2026-10-21 — dim_aircraft is SCD type 1 (attributes are overwritten). Reason: there is nothing to track — the catalogue is a single static 2025-08 snapshot with no change over time; SCD1 is chosen for that reason, not because it is simpler. SCD2 would add validity columns, change detection in the dimension load, time-range joins when loading facts, and a current-versus-at-the-time distinction in every query. Revisit condition: if a second catalogue snapshot is ever loaded, the SCD type must be reconsidered; the surrogate key keeps a later switch to SCD2 possible without redesigning the fact tables — decided by: user (confirming agent's proposal)
- 2026-10-21 — Operator is an attribute of dim_aircraft, not a dimension of its own. Reasons: it has few attributes of its own (operator ICAO, IATA and callsign in the catalogue; staging.aircraft currently keeps only the name and the ICAO code); it is filled for only 5.2% of catalogue rows, 26.7% of observed aircraft and 33.5% of observed positions; and no fact table in this model has the operator as its grain — the operator is only ever reached through the aircraft. A separate table would snowflake the model and add a join to every operator query, for no analytical gain — decided by: user (confirming agent's proposal)
