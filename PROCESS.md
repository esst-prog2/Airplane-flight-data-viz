# Promo-page process log

A step-by-step record of building the project's GitHub Pages promo page (a class
exercise). One row per step: the step, what the tool did, and what I decided.

| Step | What the tool did | What I decided |
| --- | --- | --- |
| 1. Setup | Confirmed Impeccable (`pbakaus/impeccable`) is installed via `/plugin`, and the gstack skill suite (`garrytan/gstack`) is cloned into `~/.claude/skills/gstack` (its `/office-hours` content skill is reached through the `/gstack` router). Started this `PROCESS.md` and the convention of committing and logging a row after each step. | Use the course tools (gstack for content, Impeccable for the look). The page and this log live in the main repo (`esst-prog2/Airplane-flight-data-viz`), published via GitHub Pages. Nothing personal goes on the page. |
| 2. Content (gstack `/office-hours`) | gstack's scripts are blocked by the session sandbox, so office-hours ran in its documented degraded mode (no telemetry/brain). Ran the office-hours interview method and wrote `docs/promo-content.md`: a two-audience content brief (a casual live-map section and a short technical taste: continuous collection, staging, a Kimball star schema on Postgres/Docker) with CTAs to the live dashboard and the GitHub repo. | Broad audience: a casual part (just the live map) plus a technical taste for developers, with the full GitHub project for anyone who wants more. One takeaway in two parts: a simple map with real data behind it, and the data-engineering keywords. Include the GitHub link. Keep the title "Central European Air Traffic". Approved the draft with no changes. |
| 3. The look (Impeccable: shape, generate, critique) | `impeccable context` required a product record, so wrote `PRODUCT.md`. `concept-seed` dealt six visual worlds; I presented three product-grounded directions (the browser decision page needs a local server the sandbox blocks, so the pick ran through the structured menu). Built `docs/index.html` as static HTML/CSS in the chosen world. The design detector flagged low-contrast (fixed) and colored-glow shadows (tempered the button glow to neutral elevation; kept the world's purposeful glow); it then passed. Ran a three-persona critique (classmate / teacher / stranger). | Picked the "Night sky traffic" direction: a dark page with a glowing live-map hero, cool-to-warm density glow, one bright accent on the primary CTA. Kept the glowing world. Accepted the built page. Critique's weakest point was no real dashboard screenshot; added one (`docs/dashboard.png`) as a framed, clickable product shot in the "What you see" section, which addresses it. |
| 4-5. Publish and push | Merged the promo-page PR into `main`, so `docs/` is on the default branch. Enabled GitHub Pages (source `main` / `/docs`, HTTPS enforced, repo public); the Pages build reports `built`. Verified the live page returns HTTP 200 with the title "Central European Air Traffic", the hero, the dashboard screenshot, and the live-dashboard and GitHub links. | Publish from the project repo's `main` branch `/docs` folder. The page is live at **https://esst-prog2.github.io/Airplane-flight-data-viz/** — the submission URL. |
| 6. Promo video (HyperFrames) | Node 22+ was present but the session sandbox blocks `npx` and had no FFmpeg, so I authored the composition and the user rendered it. Wrote `video/index.html`: a deterministic 30s / 1080p / silent "A day over Central Europe" data time-lapse (one paused GSAP timeline; `onUpdate` redraws the scene from a master progress, so every seeked frame is reproducible), in the page's "Night sky traffic" look, driven by the real daily-presence curve shape and real numbers (peak ~806 aircraft, 7.7M+ positions). Checked frames with `hyperframes snapshot` (1s/12s/28s) and removed a muddy curve-panel box. The user installed FFmpeg and ran `npx hyperframes render` → `docs/promo.mp4` (6.5 MB). Embedded it on the promo page as a muted autoplay-loop `<video>` with a poster frame (`docs/promo-poster.jpg`, 12s) and an honest caption that it is a stylized time-lapse of the real pattern; nothing else on the page changed. | Idea A of three — "a day over Central Europe, sped up" (the data time-lapse, the app at its best) over the pipeline story (B) and a dashboard walkthrough (C), because it adds the rhythm of a day that a static map and screenshot cannot show. Keep it muted (works without sound) and autoplay-looping. |
